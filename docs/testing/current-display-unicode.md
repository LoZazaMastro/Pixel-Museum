# Current display Unicode coverage

`tools/font_display_text.py` inventories the fields actually read by the native catalogue and public Credits, including narrative features, soundtrack rooms and reviewed language overlays. Raw research descriptions, ingestion notes, source snapshots, model node names and selection queries are excluded. Text and credits are never shortened or removed to make the audit pass.

`tools/bake-fonts.sh` now refreshes that inventory and the official Noto CJK subset before every bake, then audits the live source again. `tools/audit-font-coverage.py` no longer trusts a stale `build/catalog-codepoints.txt`: it checks source/request hashes and all ordinary characters against each of the four actual interface faces and their fallbacks. `tests/font-display-inventory.py` verifies the inclusion/exclusion boundary with independent fixture fields.

The current 1398-entry source57 checkpoint contains 915 non-ASCII display codepoints, including the newly included Japanese soundtrack names. All 874 ordinary characters are covered across all four faces. At the initial audit, 300 of the reported 367 gaps occurred only in hidden metadata, while 44 displayed ordinary characters needed genuine additional glyphs. The 41 Arabic/Indic codepoints in the current live display inventory require contextual shaping rather than a claim based on individual glyph presence.

The fallback now includes genuine glyphs from official OFL Noto Sans Math and monochrome Noto Emoji sources. The derived font is renamed; individual source URLs, SHA-256 values and licences are retained. Emoji outlines are rendered as monochrome text, matching this SDF renderer. Source texts, including stylized creator names, are unchanged. The existing fallback atlas remains a single 2048-pixel-wide texture; no extra runtime font or GPU texture was added.

`MUSEUM_SCRIPT_PROTOTYPE=1 MUSEUM_PREVIEW_4K=1 MUSEUM_PREVIEW_ROOT=build/runtime-preview bash tools/preview.sh unicode-fonts` loads the actual Screen fonts against the frozen runtime and checks all 874 ordinary codepoints, 867 visible glyph geometries and NBSP advances across regular, semibold, display and mono. Visible glyphs must use genuine atlas rectangles rather than the question mark's. Both real 3840×2160 theme renders pass GL checks and were inspected: `build/previews/unicode-fonts-{dark,light}-4k.png`.

The nine current complete Arabic, Tamil, Bengali and Devanagari phrases are now shaped offline by actual HarfBuzz 10.2.0 with genuine OFL Noto script fonts. `tools/prepare-script-runs.py` preserves glyph positions, contextual forms and ligatures, and bakes 26 complete phrases/word-boundary subphrases into the existing fallback atlas. The original UTF-8 catalogue, translations and public credits remain unchanged. Source font hashes, HarfBuzz glyph/cluster output and exact source phrases are recorded in `build/research/offline-script-shaping/script-runs.json`.

The fallback uses the bounded huifont v2 trailer: exact UTF-8 key plus one internal glyph reference. The native reader retains v1 compatibility, rejects malformed or oversized trailers, and uses exact run matching consistently in measurement, layout, fitting and wrapping. Whole-word subphrases allow source-preserving wrapping without breaking Indic consonant/vowel forms. The 26 mappings occupy 696 bytes; the current single fallback atlas is 2048×2055 (4,208,640 R8 texel bytes, 4,231,888-byte font file). The baker supports a bounded rectangular maximum height of 4096 without shrinking glyphs or changing their metrics. Screen font reads alone have a 10 MiB bound so a correct atlas slightly over the old generic 4 MiB file limit can load; global save/JSON/model limits are unchanged. No new native HarfBuzz dependency, font texture slot or text replacement is needed. A v2-capable executable must accompany the new fallback asset.

The actual GL test also selects twelve Japanese glyphs with the lowest atlas positions and renders each in all four faces and both themes. Every glyph cell must contain real foreground pixels. This verifies rectangular header dimensions, UV normalization and texture upload beyond the previous square bound, rather than only checking a glyph list. Both `unicode-atlas-extended-{dark,light}-4k.png` captures pass; the queried software-host texture limit is 16384. No new physical PS5 texture-limit reading is claimed.

`tests/font-shaped-runs.sh` checks 104 phrase/face combinations against independent HarfBuzz advances and baked outline geometry, UTF-8 preservation, wrapping/fit, RTL cluster order, unknown joined-word rejection and six malformed trailers. The actual GL test renders all nine original UTF-8 phrases on both themes (`build/previews/script-runs-runtime-{dark,light}-4k.png`) and an unchanged Iraq article containing Arabic. This is support for the exact packaged static phrases, not a general dynamic complex-script or bidi layout engine. New unsupported phrases/scripts cause the bake audit to fail rather than silently claiming support.

No console transfer or physical PS5 rendering verification occurred during these font/host checks. The final native executable hash and asset/source hashes are recorded separately in `build/research/offline-script-shaping/verification.json`.
